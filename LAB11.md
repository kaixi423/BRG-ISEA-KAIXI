Tried to test it but had a permission denied, I went on google and found out that the /var/log folder belongs to the system administrator root user and a regular user like azureuser is not allowed to create or write files in that user unless it is under administrative control.
To fix this I have to ensure that the log file is created with the right permissions.

I found on google to use sudo touch, it uses admin powers to create the empty task.log file inside then protected /var/log directory.
I also needed to use sudo chmod 666 which changes the permissions of that log file so that my script is allowed to write text in it.
I did not understand what the 666 meant so I googled it and it is a permission code. 
In linux, file permissions are broken down into three numbers, Owner (the person who created the file), Group (a group of users who can use the file), Others (anyone else who has access to the file or system). 
The number 6 is calculated by adding up individual permission values, Read = 4, write = 2 and execute = 1.
I was confused as to how Read = 4, write = 2 and execute = 1 so I googled it. 
I found out that it comes down to binary code (base 2 math) which is how computers think at their lowest level. The 3 bit binary switch, a 1 means the switch is ON and a 0 means the switch is OFF. 
They established a universal order for the permissions rwx, so in the computer’s brain (binary code) a 3 digit slot would look like this.
